# miime-2.1 Annotation Vocabulary Implementation Plan

**Implementation status (2026-11-03):** Tasks 1–10 implemented and reviewed using Luna subagents. Build, full tests, deterministic renders, and seven legacy PNG hash guards pass. The existing 2.0 foundation and 2.1 implementation are delivered together on `codex/miime-2.1-annotation-vocabulary`; the per-task commit commands below describe the original intended sequence rather than separate historical commits.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the AI a real annotation vocabulary (Excalidraw-class primitives, ink control, `som_id` targeting, self-placing labels) while keeping every old request byte-identical.

**Architecture:** Extend the hand-rolled JSON parser in `schema.c` to round-trip new optional fields (change nothing when absent); promote alias types to real enum primitives in `annotate.h`/`sketch.c`/`render.c`; add `freehand.c` for pointer-like Catmull-Rom strokes; wire `layout.c` into `handle_render`; emit real tool `inputSchema`s; add deterministic golden tests.

**Tech Stack:** C99, glib-2.0, cairo, pango, Python 3 (integration test only).

## Global Constraints

- C99; build flags from `Makefile` (`-Wall -Wextra -Werror` on MCP and TEST targets) — no new warnings allowed.
- **Backward compat:** a request with no new fields must produce byte-identical output vs pre-2.1. New fields are opt-in.
- **Build + verify per task:** `make test` must pass end-to-end (it rebuilds `test_*` + `miime-mcp` + MCP python check).
- All new public functions prefix `miime_`; add prototypes to the matching `src/*.h`.
- **Serialize→deserialize→serialize is idempotent** — this is the repo's existing invariant (`tests/test_bidir.c`); keep it green.
- Render must stay deterministic: same input ⇒ same PNG bytes.

## Confirmed decisions (from spec open questions; not to be revisited)

- `highlight_box` renders as a normal rect (no auto translucent wash). Translucent look is reachable via `fill:"solid", fill_color:[r,g,b,a]` with low alpha. `z` defaults to `normal`.
- `callout` tail is **auto**: bubble drawn at the target; tail tip points at the nearest edge midpoint of the target box (by bubble-center distance). No explicit `tail:[x,y]` in 2.1.
- `pin` auto-numbers sequentially from the count of existing `MIIME_ANNOT_PIN` in the current stack.
- `spacing_ruler` has **caller-supplied** label text only; no auto length text is derived from pixel span.
- `dry_run` is **included** in 2.1; it is an optional boolean on `render_ux_annotations` and `patch_ux_annotations` that returns placements JSON instead of the PNG (see Task 9).

## Review Focus (the five ways this ships broken)

Pinned by dedicated tests (see Task 3, Task 1, Task 9 respectively):

1. **Malformed/missing registry JSON for `som_id`** — `miime_som_lookup_json` returns FALSE; `handle_patch`/`handle_render` must not crash and must not draw at (0,0).
2. **Unknown `som_id`** — the MCP call must return a JSON-RPC error, never a silently-at-origin render.
3. **`stroke_width` type zoo** — scalar accepted, 2-element number array (taper) accepted, anything else rejected with an error *before* pushing to the stack.
4. **Layout with > `MIIME_LAYOUT_MAX_ITEMS` (64) label items** — clamp; overflow items are dropped with `obstacle_detour = 1`; no heap overflow.
5. **UTF-8 / near-limit text** — `strncpy` bounded at 256; pango measurement uses UTF-8 bytes; a 255-byte string must not crash.
