# MIIME 2.0 — Agent-Harness Visual Feedback Engine

> **Version:** 2.0 (design spec, no implementation yet)
> **Date:** 2026-11-02
> **Status:** Brainstorming / planning only — no code, no code files.
> **Supersedes:** `docs/superpowers/specs/2026-09-28-miime-design.md` (v1 viewer/annotator) for the 2.0 scope. v1 remains the shipped baseline; 2.0 layers the agent-harness capabilities on top of it.

---

## 0. Executive Summary

MIIME v1 is a fast, lightweight Linux image viewer + manual annotator (C/GTK4/Cairo). A human opens an image, picks a tool, drags the mouse, types text, saves a flat PNG.

MIIME v2 turns that same engine into a **programmatic visual feedback engine for agent harnesses**. Instead of a human dragging a mouse, an LLM/VLM agent emits a **declarative JSON annotation batch**; MIIME renders it onto a clean screenshot with spatially-grounded, collision-free, hand-drawn-looking callouts; returns the rendered image to the agent for **self-verification**; and (optionally) hands the same JSON + image to a human who can drag/edit/draw back.

The defining shift: from *input-driven drawing* (mouse events) to *state-driven drawing* (a single `annotations[]` array is the source of truth, fed by humans **or** agents). Everything in v1 (viewer, zoom/pan, export, clipboard) is retained; v2 adds the grounding, layout, sketch-rendering, tool-schema, and bi-directional-sync layers.

Core idea borrowed from the Set-of-Mark (SoM) literature: VLMs are bad at raw pixel regression but excellent at discrete token selection. So we never ask the agent to guess `[x1,y1,x2,y2]` on a 1920×1080 screenshot. We pre-tag every UI element with a numbered badge on a *reference* image the agent sees, keep the *clean* image for the user, and let the agent address elements by ID.

## 1. Goals & Non-Goals

### Primary Goals
- **Spatial grounding**: never let the VLM hallucinate coordinates. Pre-extract UI element bounds (DOM when available, CV/ML when not) and expose them as numbered Set-of-Mark IDs plus a normalized 0–1000 in-canvas grid.
- **Declarative batch annotation**: 2–3 high-level tools, not 10 micro-tools, so an agent can execute a full review in one turn.
- **Collision-free, designer-grade layout**: callout cards, leader arrows, spacing rulers, alignment redlines that never overlap each other or the UI being critiqued; auto-expand canvas margins when dense.
- **Sketch aesthetic**: hand-drawn-looking circles, arrows, boxes (seeded, deterministic, no jitter on redraw) with high-contrast "sticker" halos so they read on any background.
- **Self-verification loop**: render → return image to agent → agent inspects → patch → re-render, before the user ever sees it.
- **Bi-directional sync**: the same JSON layer loads into the interactive viewer; a human can move/delete/draw and feed changes back to the agent.
- **Headless-capable**: an agent harness (MCP/CLI) must be able to drive MIIME without a visible window — produce annotated PNG/WebP buffers.
- **Preserve v1 constraints**: cold start < 200 ms, idle RSS < 40 MB, zero CPU at idle, event-driven redraws, ~200–400 lines/file.

### Non-Goals (v2)
- No model training, no bundled LLM. MIIME is a *rendering/grounding engine*; the VLM lives in the harness.
- No cloud/SaaS backend. Everything local, offline-capable.
- No pixel-perfect Figma parity. "Senior designer sketch on an iPad" aesthetic, not polished vector export.
- No multi-user real-time collaboration (v2 is single-user + agent).
- No full computer-use automation (clicking/typing on screen) — MIIME annotates; it does not drive the OS. (Prior art: OmniParser/kira-mcp handle that layer; MIIME can *consume* their element lists.)

## 2. Competitive / Prior-Art Landscape (research)

| Tool / Work | What it does | What MIIME v2 borrows / differentiates |
|---|---|---|
| **Set-of-Mark (Microsoft, arXiv 2310.11441)** | Overlay numbered marks on image regions; VLM grounds better. | Core grounding technique. MIIME adds the *rendering* side and the clean-vs-reference dual buffer. |
| **OmniParser v2 (Microsoft)** | YOLO icon detector + Florence captioner + EasyOCR; tokenizes UI. | Static-image fallback for SoM extraction when no DOM. MIIME can call an OmniParser endpoint as a backend. |
| **UGround / ScreenParse (Microsoft)** | Dense screen parsing, universal visual grounding. | Informs the "complete screen parsing" ambition; v2 targets web screenshots primarily. |
| **agent-canvas (edrouhard)** | Spec-driven design QA, annotated screenshots, fix lists, GH issues. | Similar end goal; MIIME is the *engine* (C, local, fast) rather than a skill pack. |
| **Markup / Pincue / onUI** | Chrome extensions: pin notes to DOM selectors, export markdown briefs, MCP read-back. | Human→agent feedback loop. MIIME generalizes to arbitrary screenshots (not just live DOM) and adds agent→human annotated images. |
| **Screenote** | Agent captures → human marks → agent retrieves cropped regions. | Confirms the round-trip value; MIIME adds SoM grounding + collision layout + sketch style. |
| **ViewGraph** | DOM capture + 41 MCP tools, token-efficient UI context. | Complementary: ViewGraph supplies DOM context; MIIME supplies the *annotated image*. |
| **BugShot / ComiRadar** | Screenshot → annotate (pins/arrows/rects/freehand) → MCP read-back. | Closest cousin; MIIME differentiates via SoM grounding, layout engine, sketch math, headless mode. |
| **UI Verify** | Visual regression testing with AI judge on PRs. | Adjacent (CI gating); MIIME is interactive review, not regression baselines. |
| **kira-mcp / glovebox-mcp / desktop-control-mcp** | Local MCP servers: OmniParser + mouse/keyboard control. | MIIME is the *annotation* counterpart; could be composed with these for full computer-use. |

**Key research conclusions carried into the spec:**
1. SoM turns coordinate regression into token selection — adopt as the default grounding mode.
2. Prune DOM nodes aggressively (visibility, occlusion, semantic priority, IoU dedup) to 50–120 targets, never dump 1500 nodes.
3. Hybrid addressing: element IDs for tagged components, normalized 0–1000 grid for empty space.
4. Deterministic seeded PRNG for sketch rendering (no redraw jitter).
5. Mandatory self-verification loop before showing the user.

## 3. System Architecture

### 3.1 Dual-Buffer Model (the golden rule)

MIIME v2 maintains **two parallel image buffers** plus a hidden registry:

- **Buffer A — Clean Source**: the raw, unedited screenshot. All final doodles/callouts/arrows are composited onto this for the user. Never shown to the agent with marks.
- **Buffer B — Reference Map**: a disposable clone of A, tattooed with SoM numbered badges, a normalized 0–1000 coordinate grid with in-canvas intersection watermarks, and (optionally) category-colored outlines. **Only the VLM sees B.**
- **Grounding Registry (JSON, in harness memory)**: maps every visual tag `#N` → exact pixel geometry + computed telemetry (margin/padding, font-size, contrast ratio, WCAG pass/fail). Token-efficient: compact single-line records or a markdown table.

### 3.2 Layer Model (extended from v1)

```
┌──────────────────────────────────────────────────────────────┐
│  GtkWindow / Headless surface                                │
│  ┌────────────────────────────────────────────────────────┐   │
│  │  MiimeCanvas (GtkDrawingArea) or headless Cairo sfc    │   │
│  │  ┌──────────────────────────────────────────────────┐  │   │
│  │  │ Layer 5: Callout cards + numbered anchor badges  │  │   │  ← z-top
│  │  │ Layer 4: Leader lines / arrows                    │  │   │
│  │  │ Layer 3: Target highlight boxes                   │  │   │
│  │  │ Layer 2: Alignment redlines & spacing rulers      │  │   │
│  │  │ Layer 1: Spotlight dimming mask (optional)        │  │   │
│  │  │ Layer 0: Base screenshot + margin gutters         │  │   │  ← z-bottom
│  │  └──────────────────────────────────────────────────┘  │   │
│  └────────────────────────────────────────────────────────┘   │
│  ┌──────────────┐ ┌──────────────┐ ┌────────────────────┐    │
│  │ Toolbar      │ │ Color/Stroke  │ │ Grounding panel    │    │  ← v2: SoM legend
│  └──────────────┘ └──────────────┘ └────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 Data Flow (v2)

```
User URL or screenshot
        │
        ▼
  image.c: load base → Buffer A (clean)
        │
        ├──▶ grounding.c: extract SoM (DOM via headless browser, or CV/ML)
        │       └──▶ Buffer B (reference map) + Grounding Registry
        │
        ├──▶ (agent turn) VLM sees Buffer B + registry
        │       └──▶ emits render_ux_annotations JSON batch
        │
        ▼
  annotate.c (v2): JSON → MiimeAnnotation[] state (single source of truth)
        │
        ├──▶ layout.c: collision-free placement (margin rail / in-canvas)
        │
        ├──▶ render.c: sketch renderer composites onto Buffer A → annotated PNG
        │
        ├──▶ return annotated image to agent for self-verification
        │       └──▶ (optional) patch_ux_annotations → re-render
        │
        └──▶ (human turn) load JSON+image into interactive viewer
                └──▶ human edits → JSON delta → (optional) back to agent
```

### 3.4 Module Decomposition (v2 additions)

v1 modules retained: `main`, `window`, `canvas`, `image`, `annotate`, `tools`, `render`, `clipboard`, `keybinds`.

New v2 modules:

| Module | Responsibility | Dependencies |
|---|---|---|
| `grounding` | SoM extraction: DOM pruning (when URL), CV contour fallback (static), OmniParser client (optional). Builds Buffer B + Registry. | `image` |
| `layout` | Text pre-measurement, candidate scoring (8-position), margin-rail stacking, force relaxation, leader routing, z-order. Pure math, no Cairo. | `annotate` |
| `sketch` | Seeded PRNG + perturbed lines/circles/arrows/hachure/variable-width/halo. Consumes annotation structs, emits Cairo paths. | `annotate` |
| `schema` | JSON schema validation + (de)serialization for the 3 tools; bidirectional JSON↔struct. | `annotate`, `grounding` |
| `headless` | Windowless Cairo surface pipeline for MCP/CLI export (no GTK). | `render`, `layout`, `sketch` |
| `mcp` (optional, separate binary `miime-mcp`) | MCP server exposing `prepare_ux_canvas`, `render_ux_annotations`, `patch_ux_annotations`. | `schema`, `headless`, `grounding` |

Design notes (carried from v1): leaf modules (`annotate`, `image`, `layout`, `sketch`) have zero GTK deps → unit-testable. `tools` converts input→data; `render` consumes data. Target ~200–400 lines/file.

## 4. Tool Schema (Agent-Facing)

MIIME v2 exposes **three** high-level tools. (Full JSON schemas already drafted in the v1 conversation; summarized here.)

### 4.1 `prepare_ux_canvas`
Ingestion & grounding. Input: `source_type` (`url` | `image_path`), `source`, optional `viewport`, `visual_aids` (SoM badges, normalized grid, WCAG audit). Output: Buffer B image (attached) + compact Grounding Registry records.

### 4.2 `render_ux_annotations`
Core declarative drawing. Input: `canvas_config` (`layout_mode`: auto/margin_rail/in_canvas_floating; `aesthetic_style`: rough_sketch/clean_technical; `spotlight_dimming` bool) + `annotations[]` (1–15). Each annotation: `id`, `primitive`, `severity` (critical/warning/suggestion/positive), `category`, `target` (hybrid addressing), `label_title` (≤35 chars), `comment` (≤220 chars), `preferred_label_anchor`.

Primitives: `highlight_box`, `freehand_circle`, `callout_pin`, `spacing_ruler`, `alignment_redline`, `flow_arrow`.

Target addressing modes (discriminated union): `single_som_id`, `som_pair`, `som_group`, `normalized_grid_box` ([x_min,y_min,x_max,y_max] 0–1000), `normalized_point_to_point` ([x1,y1,x2,y2] 0–1000).

### 4.3 `patch_ux_annotations`
Self-correction without redrawing everything. Input: `operations[]` (`update`/`delete` by id, with optional new target/comment/anchor) + optional `canvas_config_override`. Used in the verification loop.

### 4.4 Hybrid Addressing Rules (enforced via system prompt)
1. Prefer `single_som_id` for any tagged component — never guess coords for a tagged element.
2. `som_pair` for relational spacing/flow between two elements (spacing_ruler, flow_arrow).
3. `som_group` for alignment/group hierarchy (alignment_redline + axis).
4. `normalized_grid_box`/`point_to_point` **only** for untagged regions or negative space, read from in-canvas watermarks.

## 5. SoM Preprocessing Pipeline

### 5.1 Dual-Image + Registry (§3.1) — mandatory.

### 5.2 Track 1: DOM Bounding-Box Extraction (for live URLs)
Run via a headless browser (Playwright/CDP) when `source_type=url`:
- **Prune** 1200+ nodes → 50–120 meaningful targets using: visibility/viewport check; occlusion culling via `elementFromPoint` at center + corners; semantic/interactive priority (button/a/input/role=button, h1–h6, p, label, img, svg); structural dedup via IoU (>90% parent-child overlap → keep innermost unless parent has distinct visual boundary).
- **Telemetry**: extract `getComputedStyle` → margin, padding, border, font-size, font-weight, line-height, color, background-color; pre-compute WCAG contrast ratio.
- **Non-overlapping tag placement**: dashed outline + numbered pill badge at top-left outside corner; slide badge along perimeter if collision; color-code by semantic role (magenta interactive, cyan typography, yellow containers).

### 5.3 Track 2: Coordinate Grid Fallback (raw screenshots / empty space)
- Normalized 0–1000 axis lines: 10×10 major (100 units) + 20×20 minor (50 units).
- Adaptive contrast: dual-stroke (dark line + 25% white outer glow) or difference blend so grid reads on any background.
- **In-canvas intersection watermarks**: print `x,y` at every major grid crossing inside the canvas (e.g. `200,300`) so the VLM has a coordinate reference within ~50 px of any gaze point. This is the "secret sauce" for negative space.

### 5.4 Track 3: Visual-Only Detection (no DOM)
For static PNG/JPG without a URL:
- Tier 1: classical CV (Canny edges + morphological dilation) → rectangular contours → SoM IDs. Zero GPU, instant.
- Tier 2 (optional): lightweight ONNX UI detector (OmniParser-class YOLO + OCR) for near-DOM accuracy. MIIME calls an external endpoint (configurable URL); does not bundle weights.

### 5.5 Agent Grounding Rules (system prompt)
Cap 5–10 high-impact annotations; prefer `margin_rail` for ≥5 or dense UI; vary primitives; punchy actionable copy (title ≤35 chars naming problem+metric; comment ≤220 chars with concrete remedy); include at least one `positive` annotation for balance; mandatory self-verification loop.

## 6. Layout Engine (Collision-Free Placement)

Solves the Automatic Label Placement Problem with a deterministic 4-stage pipeline (math specified in v1 conversation; summarized).

### Stage 1 — Text Pre-measurement
Greedy line-break at max width (240 px), clamp label width, compute height from line count + header + padding. Off-screen font metrics (Pango/Cairo) — never measure on-screen.

### Stage 2 — Layout Mode Selection
- **Margin Rail** (≥5 annotations or dense UI): expand canvas by 300 px gutters left+right; bipartite partition (target center left/right of image midline); topological vertical sort (higher target → higher label) guarantees non-crossing leader arrows; 1D sweep with min-gap, reverse sweep if overflow.
- **In-Canvas Floating** (1–4 annotations, ample whitespace): 8 candidate positions per target at offset `d=24 px`; score each by overlap with targets (w=1000), OOB (w=1000), other labels (w=500), un-annotated DOM elements (w=50), visual busyness variance (w=10); pick lowest.

### Stage 3 — Force Relaxation
15-iteration spring-repulsion: repulsion MTV between overlapping labels/targets (12 px safety buffer); spring anchor (Hooke's law) toward initial candidate to prevent drift; boundary clamping inside `[8,8,W-Wlabel-8,H-Hlabel-8]`.

### Stage 4 — Leader Routing
- Nearest perimeter port selection (label: 4 midpoints; target: 4 midpoints + 4 corners) with outward-normal dot-product constraint.
- Curve style: smooth S-curve (cubic Bézier with control points projected along normals at 0.4×span) for `rough_sketch`; orthogonal elbow (stub 20 px → diagonal → arrowhead aligned to final tangent) for `clean_technical`.
- Obstacle avoidance: Liang-Barsky line-rect intersection test; if hit, route through padded corner as quadratic Bézier midpoint.

### Z-Index (painter's algorithm, back→front)
0 Base + gutters → 1 Spotlight mask → 2 Redlines/rulers → 3 Highlight boxes → 4 Leader arrows → 5 Callout cards + anchor badges.

## 7. Sketch / Hand-Drawn Rendering

Goal: look like a senior designer sketching on an iPad, not stamped geometry. Four biomechanical effects: ballistic overshoot, mid-stroke bowing, multi-stroke overlap, velocity-based tapering.

### 7.1 Deterministic Seeding (critical)
Hash the annotation `id` (e.g. cyrb128/Murmur3) → Mulberry32 PRNG. Every perturbation calls `rand()` from that seed. Result: each annotation has a unique organic shape that is **frozen across redraws** (no jitter on pan/zoom/label update). Never use `Math.random()` in the render loop.

### 7.2 Primitives
- **Perturbed straight line**: endpoint jitter + overshoot along normal; two cubic Bézier control points at 1/3 and 2/3 with shared signed bowing term (clamped 8 px) + high-freq tremor; double-stroke (full-opacity 2.5 px + 45%-opacity 1.2 px ghost). Used by boxes, rulers, arrows.
- **Designer loop circle/ellipse**: angular span `2π + 0.25–0.55 rad` overlap; low-frequency radial drift (sin/cos harmonics + linear spiral drift ~4 px) so the tail visibly loops; Catmull-Rom → cubic Bézier. Not a closed 360° ellipse.
- **Sketchy arrow**: subdivide leader Bézier at t=0.5, offset midpoint perpendicular ±3 px; asymmetric open V-wings with independent angles (28°±5°) and lengths (14±2 px); each wing a quadratic Bézier bowed 1.5 px.
- **Hachure fill**: diagonal scanlines at −41°, 8 px spacing, zig-zag turnaround, endpoints perturbed 2–6 px inward, 15% opacity.
- **Variable-width stroke**: pressure profile `w(t)=w_base·(1−0.25 sin πt)·min(1,8t)·min(1,8(1−t))` → taper first/last 12%; build filled polygon along normals. (Or SVG filter displacement shortcut for lightweight mode.)
- **Sticker halo**: every path rendered twice — white (or #0F172A on pure white) 5.5 px under-stroke at 85% opacity, then semantic color 2.5 px over-stroke. Guarantees legibility on any background.

### 7.3 Aesthetic Modes
- `rough_sketch` (default): perturbed lines, spiral circles, asymmetric arrows, hachure fills, variable width.
- `clean_technical`: sharp geometry, orthogonal elbows, uniform strokes, no perturbation. For architecture/margin-rail callouts.

## 8. Color Semantics

Locked palette, not free-form hex (avoids clashing with the reviewed UI). Each severity auto-maps to high-contrast tokens with white outer strokes/drop-shadows:

| Severity | Color | Use |
|---|---|---|
| `critical` | Red/Coral | Broken layout, inaccessible contrast, missing CTA, overlapping text |
| `warning` | Amber/Orange | Inconsistent padding, weak visual hierarchy |
| `suggestion` | Electric Blue | Improvements, optional refinements |
| `positive` | Emerald Green | Well-executed patterns (at least one per review for balance) |

SoM badge category colors (reference map only): magenta interactive, cyan typography, yellow containers.

## 9. Self-Verification Loop

Mandatory before the user sees anything:

1. Agent calls `render_ux_annotations` → MIIME returns `annotated_image` + `layout_telemetry` (mode used, collisions resolved, warnings).
2. Agent **visually inspects** the rendered image: did any `normalized_grid_box` miss? Are leader arrows crossing UI text? High collision warning?
3. If defect → `patch_ux_annotations` (adjust coords, switch anchor, switch to margin_rail) → re-render → re-inspect.
4. Only on clean render → present to user.

Harness-side assist: because MIIME knows exact DOM geometry, if a manual `normalized_grid_box` overlaps >~65% with a SoM element `#N`, it emits a warning ("your box half-covers #N — did you mean som_id: N?"). This eliminates nearly all residual coordinate drift.

## 10. Bi-Directional Sync (Killer Feature)

The JSON annotation layer is the single source of truth; the rendered image is a *view*.

- **Agent → Human**: agent's JSON loads into the interactive viewer alongside the image; user sees doodles, can click boxes, move/delete, or draw their own, then say "look at the green box I drew — fix that container."
- **Human → Agent**: human edits serialize to a JSON delta (moved bounds, deleted ids, new annotations) that can be fed back to the agent as a patch.
- **Human-only edits** remain first-class: v1's mouse tools still push onto the same `annotations[]` stack; undo/redo unchanged.
- **No sidecar files by default** (v1 constraint preserved) — but an opt-in `--annotations-out path.json` for harness use; never auto-write next to the image.

## 11. Headless / MCP Mode

- `miime` (GUI) and `miime-mcp` (stdio MCP server) share `schema`, `headless`, `grounding`, `layout`, `sketch`. The MCP binary has no GTK dependency → builds on servers/CI.
- Headless pipeline: load image → ground → apply JSON → layout → sketch-render → write PNG/WebP to stdout or path. No window, no event loop.
- Clipboard copy in headless mode writes to a file path (no system clipboard); GUI mode keeps `Ctrl+C`.
- Performance: headless render of a 1440×900 with 8 annotations must complete < 500 ms (target), preserving the "instant" feel.

## 12. Memory & Performance Rules (v2, extending v1 §7)

1. **Two buffers, not N**: Buffer A (clean) + Buffer B (reference) only. Free B after grounding completes and registry is built; keep only if `visual_aids` re-requested.
2. **Registry is compact**: single-line records, not pretty JSON; cap telemetry to detected elements.
3. **No tile cache** for <4K (v1 rule retained).
4. **Immediate buffer release** on image navigation (v1 rule retained).
5. **Annotation stack is structs** (v1 rule retained); sketch paths are derived at render time, not stored.
6. **Seeded PRNG is stateless**: recompute from id hash each render — no stored random state.
7. **Headless has no idle CPU**: process exits after render; no daemon unless MCP mode.
8. **OmniParser/ML backend is external**: MIIME never loads multi-hundred-MB models in-process; calls a configurable HTTP endpoint, caches last result by image hash.

## 13. Phased Implementation Roadmap (v2)

### Phase 0 — Foundation (refactor, no new user features)
- Decouple annotation state from mouse events: every draw action (human or agent) pushes to `annotations[]`; `tools.c` becomes one producer among several.
- Add `schema.c` (JSON↔struct) + unit tests.
- Add `headless.c` Cairo-surface pipeline.
- **Gate**: existing v1 tests still pass; `miime --headless in.png --annotations a.json -o out.png` works.

### Phase 1 — Grounding
- `grounding.c`: DOM extraction via headless browser (Playwright) with pruning + telemetry; build Buffer B + registry.
- Coordinate grid renderer (0–1000, watermarks).
- CV contour fallback for static images.
- Optional OmniParser HTTP client.
- **Gate**: `prepare_ux_canvas` returns a SoM image + registry; < 2 s for a typical page.

### Phase 2 — Layout Engine
- `layout.c`: text measurement, 8-position scoring, margin rail, force relaxation, leader routing.
- Unit tests on known inputs (overlap cases, overflow, crossing prevention).
- **Gate**: 8 annotations on a dense dashboard render with zero overlap warnings.

### Phase 3 — Sketch Renderer
- `sketch.c`: seeded PRNG, perturbed lines, spiral circles, asymmetric arrows, hachure, variable width, sticker halo.
- Aesthetic mode toggle.
- **Gate**: visual review; no redraw jitter on pan/zoom.

### Phase 4 — Tool Surface + MCP
- `mcp` binary exposing the 3 tools; self-verification loop support (telemetry warnings).
- Patch tool.
- **Gate**: an agent harness (e.g. Claude Code via MCP) can run a full review end-to-end.

### Phase 5 — Bi-Directional Sync
- Interactive viewer loads JSON layer; human edit → delta; delta export.
- **Gate**: human moves an agent box, re-exports JSON, agent consumes delta.

### Phase 6 — Polish & Docs
- README v2, keybindings unchanged, desktop file, install.
- **Gate**: full workflow demo recorded.

## 14. Open Questions / Decisions for the Human

1. **DOM extraction host**: bundle a Playwright dependency (heavy) or require the harness to supply bounds (lighter, matches OmniParser-MCP pattern)? Recommendation: external, configurable — MIIME stays lean; harness provides bounds or MIIME calls a URL.
2. **ML backend**: ship no weights (call endpoint) vs. optional in-process ONNX? Recommendation: external endpoint only (v1 memory constraints).
3. **MCP as separate binary** vs. subcommand `miime --mcp`? Recommendation: separate binary for clean dependency isolation, but shared code.
4. **Annotation persistence default**: keep session-only (v1) for GUI, opt-in JSON for harness. Confirmed.
5. **Sketch default on/off**: should `rough_sketch` be the default aesthetic? Recommendation: yes — it's the differentiator; `clean_technical` opt-in.

## 15. Success Criteria (v2 "done")

- An agent harness can call `prepare_ux_canvas` on a screenshot/URL and receive a SoM reference image + registry.
- The agent can call `render_ux_annotations` with a mixed batch (som_id, som_pair, som_group, grid_box) and get a clean, collision-free, hand-drawn annotated image back.
- The agent's self-verification loop (render → inspect → patch → re-render) works without human intervention.
- A human can open the resulting JSON in the MIIME viewer, edit annotations, and export a delta.
- Headless render < 500 ms for typical inputs; GUI idle RSS < 40 MB; cold start < 200 ms.
- No regression of v1 viewer features.
